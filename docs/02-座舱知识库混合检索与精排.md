# 混合检索 + 精排：BGE-M3 稠密 + BM25 稀疏怎么融合

> 元境智能座舱大模型落地实战系列第 2 篇。上一篇讲了父子分块，这篇讲检索——分块做好了，检索这一步能不能"既准又全"。

---

## 一、为什么单路检索不够用

RAG 的检索，本质是把用户问题变成向量，去向量库里找最相似的文档块。但只靠一条路，总有一头顾不住：

- **稠密向量检索（Embedding）**：抓语义。用户说"把天窗打开"和知识库里的"天窗开启操作"语义接近，它能召回。但换到精确词就露怯了——功能名、条款号、专有名词，向量相似度区分度不够，容易漏。
- **稀疏检索（BM25）**：抓关键词。按词频和逆文档频率算字面命中，"座椅加热"这种精确词必中。但用户换个说法（"给屁股加热"），字面不匹配，就召不回。

一句话：**稠密路泛化强、精确弱；稀疏路精确强、泛化弱。** 单用哪条都吃亏。

## 二、混合检索：两路召回、一次融合

我的做法是在向量数据库里做**混合检索**：一次查询同时跑两路召回，再把结果融合成一路。

- 稠密路用 **BGE-M3**（一个模型同时输出稠密 + 稀疏表示，开源可私有化）
- 稀疏路用向量库内置的 **BM25**

融合是在库内完成的——一次 `hybrid_search` 传两个召回请求，用 `WeightedRanker` 加权，服务端一次算完，省一次网络往返。

这样**语义路保证"换说法也能召回"，关键词路保证"精确词必命中"**，两路互补。

## 三、权重 0.55 / 0.45 是怎么定的

这里最容易踩的坑是**拍脑袋定权重**。我的做法分三步：

1. **先各跑单路**：分别在测试集上跑纯稠密、纯稀疏，看各自强在哪类问题。
2. **网格搜索**：拿几档权重组合（比如 0.6/0.4、0.55/0.45、0.5/0.5），在测试集上比召回率。
3. **归一化前置**：两路分数**量纲完全不同**——稠密是余弦相似度（-1~1），BM25 是词频加权分（可能几十上百）。不归一化，加权等于只看大的一路，另一路形同虚设。

所以结论是 0.55/0.45，但这个数字不是重点，重点是"**先单路看强项、再网格搜索、加权前必须归一化**"这套方法。

## 四、精排：粗召回之后为什么还要 CrossEncoder

混合检索能保证"相关内容在候选里"，但不能保证"最相关的排在最前面"。所以还要**精排（Rerank）**。

这里有个模型选型的经典取舍：

- **Bi-Encoder（双塔）**：查询和文档分别编码、再算相似度。快，能全库检索，但交互浅、不够准。
- **CrossEncoder（交叉编码器）**：把"查询 + 文档"拼成一条输入一起编码，输出相关性分数。准，但逐对计算，慢。

所以标准打法就是**"粗召回用 Bi-Encoder、精排用 CrossEncoder"**：

1. 用 BGE-M3（双塔）快速召回，把候选压到 **20～30 个**；
2. 再用 CrossEncoder 在这 20～30 个候选里逐对打分，取 **Top 5** 喂给生成层。

### 为什么不能直接用 CrossEncoder 全库检索？

因为 CrossEncoder 是逐对计算，复杂度等于候选数。拿它去几十万条文档里检索，每条都拼一起算一遍，延迟和成本直接爆炸。所以必须先粗筛、再精排，**便宜的圈范围、贵的精挑选**。

## 五、踩过的坑

1. **两路分数不归一化就加权**：量纲不同，等于只走了一路。
2. **中文 BM25 分词没配好**：分词错了，关键词路整个废掉。
3. **候选不压缩就精排**：精排吃掉了整个延迟预算，P95 直接飙。

## 六、效果

父子分块 + 混合检索 + 精排这套组合拳，最终把 Top5 召回率从 **68% 提到 90%**，引用准确率 **95% 以上**。检索这层稳了，后面的生成才有据可依。

## 七、总结

可复用的三点：

1. 稠密管语义、稀疏管字面，**混合检索取长补短**。
2. 权重靠"单路强项 + 网格搜索"定，**加权前必须归一化**。
3. **粗召回用双塔、精排用交叉编码器**，候选先压到 20～30 再精排。

## 附：核心代码

```python
"""混合检索 + 精排（脱敏示意）"""
from pymilvus import AnnSearchRequest, WeightedRanker
from sentence_transformers import CrossEncoder

# 权重是网格搜索 + 测试集标定出来的，不是拍脑袋
DENSE_WEIGHT, SPARSE_WEIGHT = 0.55, 0.45
RECALL_LIMIT, RERANK_TOPK = 30, 5

# 精排模型与 embedding 同族（BGE 系），一致性更好
reranker = CrossEncoder("bge-reranker-base")

def hybrid_search(query_vec, query_text, topk=RERANK_TOPK):
    # 稠密路：BGE-M3 语义（用户换说法也能召回）
    dense_req = AnnSearchRequest(
        data=[query_vec], anns_field="dense_vector",
        param={"metric_type": "COSINE", "params": {"ef": 64}},
        limit=RECALL_LIMIT,
    )
    # 稀疏路：BM25 关键词（功能名、条款号字面必命中）
    sparse_req = AnnSearchRequest(
        data=[query_text], anns_field="sparse_vector",
        param={"metric_type": "BM25"},
        limit=RECALL_LIMIT,
    )
    # 库内加权融合：两路分数已各自归一化，再加权
    hits = collection.hybrid_search(
        reqs=[dense_req, sparse_req],
        rerank=WeightedRanker(DENSE_WEIGHT, SPARSE_WEIGHT),
        limit=RECALL_LIMIT,
        output_fields=["text", "parent_id", "version"],
    )
    candidates = [h.entity for h in hits[0]]
    # 精排：CrossEncoder 逐对打分，取 Top5 喂给生成层
    return rerank_with_cross_encoder(query_text, candidates, topk=topk)


def rerank_with_cross_encoder(query, candidates, topk=5):
    pairs = [(query, c["text"]) for c in candidates]
    scores = reranker.predict(pairs)             # 逐对打分
    ranked = sorted(zip(candidates, scores), key=lambda x: -x[1])[:topk]
    return [c for c, _ in ranked]


def grid_search_weights(test_set):
    """权重标定：在测试集上网格搜索，取召回率最高的组合"""
    best, best_score = (0.5, 0.5), 0.0
    for w in [0.6, 0.55, 0.5, 0.45]:
        score = eval_recall(test_set, weight=(w, 1 - w))
        if score > best_score:
            best, best_score = (w, 1 - w), score
    return best
```

两个关键：`hybrid_search` 一次跑两路、`WeightedRanker` 在库内完成融合；精排只处理 30 个候选，控制延迟。
