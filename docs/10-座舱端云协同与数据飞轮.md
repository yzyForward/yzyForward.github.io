# 端云协同 + 数据飞轮：座舱大模型怎么既快又省钱，还越用越准

> 元境智能座舱大模型落地实战系列第 10 篇，多智能体系列收官。架构、协议、仲裁都讲完了，最后讲两个"运营"层面的设计：端云怎么分工、数据怎么闭环。

---

## 一、端云协同：为什么不能全放云端

大模型推理天然费算力，第一反应是"全放云端"。但座舱有两个硬约束：

1. **低延迟**：唤醒、意图分类要 300ms 内响应，网络往返 + 云端推理等不起。
2. **隐私**：生物信息（人脸、语音、行为）法规要求"不出车"，不能上云。

所以要做**端云协同**，按任务特性分流：

- **端侧**（车机芯片）：唤醒、轻量意图分类、实时视觉检测——低延迟、数据不出端。
- **云端**（GPU）：多轮理解、复杂推理、多模态融合——强算力、强能力。

一句话：**端侧管"快和私密"，云端管"强和复杂"。**

## 二、端云协同的技术细节

- **端侧推理**：模型量化成 INT8（体积小 4 倍），转成 ONNX 格式，用 ONNX Runtime / TensorRT 在车机芯片 NPU 上跑。
- **云端推理**：用 vLLM 部署大模型，PagedAttention 管显存、连续批处理提吞吐。
- **降级兜底**：网络不稳时，云端不可用，端侧小模型兜底——基础功能（唤醒、简单意图、基础车控）照常，复杂能力暂时降级，网络恢复再切回。

关键原则：**端侧能独立跑，云端是增强不是依赖。** 这样网络抖动不会让座舱变哑巴。

## 三、端云协同的收益：省成本

端云协同不只是为了延迟和隐私，还省钱：

- 简单任务端侧就地处理，不上云；
- 云端只扛真正需要它的复杂推理。

我项目里靠端云切分，把云端算力成本降了约 40%。核心思路是"**能端侧的别上云，云端只处理端侧扛不住的**"。

## 四、数据飞轮：让模型越用越准

模型上线不是终点，还得持续变好。靠的是**数据飞轮**，一个闭环：

```
用户交互日志（Kafka 采集）
        ↓
接管率分析 + Bad Case 挖掘
        ↓
SFT/LoRA 微调小模型 + Prompt 优化大模型
        ↓
评测回归 → 灰度上线
        ↓
再采集（回到开头）
```

几个关键点：

1. **不是"存日志"，是"反馈变训练数据"**：日志要能变成模型改进的输入。
2. **小模型微调、大模型调 Prompt**：意图分类、视觉检测这些小模型用 LoRA 微调（成本低、见效快）；大模型用 Prompt 优化（微调成本太高）。
3. **Bad Case 要人工复核**：不然垃圾数据喂进去，越训越偏。

## 五、数据飞轮的实例

以意图识别为例：

- 从日志里按**接管率**挖 Bad Case——用户打断、纠正的样本，大概率是识别错的；
- 人工复核后，按意图类别**定向采样**（重点补低频意图）+ **数据增强**（同义改写、噪声注入）；
- LoRA 增量微调意图分类小模型；
- 评测回归通过后灰度上线。

这一套循环，把语音指令识别准确率从 **82% 提到了 95%**。

## 六、总结

可复用的三条：

1. 端云分工按"**低延迟/隐私放端侧、复杂推理放云端**"，端侧要能独立兜底。
2. 端云切分不只为了体验，**也是控成本**——能端侧别上云。
3. 数据飞轮的核心是"**反馈 → 训练数据 → 模型更新 → 再采集**"的闭环，Bad Case 要人工复核。

```python
"""数据飞轮 + LoRA 微调（脱敏示意）"""
import json
from peft import LoraConfig, get_peft_model
from confluent_kafka import Consumer

# LoRA 配置：只训投影层 + 注意力 q/v，基座冻结
lora_config = LoraConfig(
    r=16, lora_alpha=32,
    target_modules=["visual_proj", "q_proj", "v_proj"],
    lora_dropout=0.1,
)
model = get_peft_model(base_model, lora_config)

def consume_bad_cases(topic="cockpit-logs"):
    """从 Kafka 按接管率挖 Bad Case"""
    consumer = Consumer({"bootstrap.servers": "localhost:9092",
                         "group.id": "badcase-miner"})
    consumer.subscribe([topic])
    while True:
        msg = consumer.poll(1.0)
        if msg is None:
            continue
        log = json.loads(msg.value())
        if log["takeover_rate"] > 0.3:   # 用户频繁打断 = 识别错
            yield log

def train_on_bad_cases(bad_cases):
    # 定向采样 + 数据增强，再 LoRA 微调
    train_set = augment(oversample_low_freq(bad_cases))
    model = train(model, train_set, lr=1e-4, epochs=3)
    return model
```

关键：飞轮闭环里，微调的是小模型（意图分类/视觉检测），大模型只调 Prompt；Bad Case 必须人工复核后才进训练集。
