# 误报率 8% 降到 3%：疲劳检测怎么靠级联 + 数据飞轮压下来

> 智能座舱大模型落地实战系列第 15 篇，收官。多模态里有一个体验杀手：疲劳检测的误报——没困被反复提醒，用户会直接关掉整个主动服务。这篇讲怎么把误报率压下来。

---

## 一、问题：误报是主动服务的头号杀手

疲劳检测的逻辑是"检测到疲劳 → 主动提醒休息"。但**误报**的代价很大：

- 用户没困，系统一遍遍提醒"您累了，休息一下"，烦；
- 多几次，用户就把整个主动服务关了——**一次误报，毁掉整个功能的信任**。

所以误报率是疲劳检测最核心的指标。

## 二、方案一：端侧 + 云端级联

降误报的第一个手段是**级联**：

1. **端侧轻量检测**先做初筛——快、召回高（尽量别漏），但可能有误报；
2. **云端大模型（Qwen3-VL）**对端侧拿不准的样本做**二次判定**——准、慢。

用级联把"快但不准"和"准但不快"结合：**大部分样本端侧就处理，拿不准的再上云复核。** 这样既保住实时性，又把误报滤掉一层。

## 三、方案二：数据飞轮持续微调

级联能滤掉一部分，但根本的优化还是要**持续微调模型**：

```
日志采集 → Bad Case 挖掘 → 人工复核 → LoRA 微调视觉小模型 → 评测回归 → 灰度上线 → 再采集
```

关键是把线上误报的样本挖出来，喂回训练，让模型越训越准。

## 四、一个最容易踩的坑：误报和漏报不能混

疲劳检测有两个指标，**优化方向是相反的**：

- **误报**：没困被提醒 → 体验差；
- **漏报**：困了没提醒 → 安全隐患。

它们对阈值的要求正好相反：

- 阈值调低：漏报少，但误报多；
- 阈值调高：误报少，但漏报多。

所以**误报和漏报必须分开统计、分开优化**，不能混在一起调阈值——否则两头不讨好。Bad Case 也要分"误报""漏报"两类，分别微调。

这也是疲劳检测这类安全功能比普通分类难的地方：**不能只盯一个指标，要在体验和安全之间走钢丝。**

## 五、结果

靠"级联 + 数据飞轮持续微调"，疲劳/分心误报率从 **8% 降到了 3%**。

8% 意味着每 12 次提醒有 1 次是误报，用户很快就烦了；3% 以内，配合防打扰策略（高危静默、频率控制），体验才立得住。

## 六、总结

可复用的三条：

1. 误报是主动服务的头号杀手，**级联（端侧粗筛 + 云端复核）先滤一层**。
2. **数据飞轮持续微调**才是根本，把线上误报样本挖出来喂回训练。
3. **误报和漏报优化方向相反，必须分开统计、分开优化**，不能混着调。
