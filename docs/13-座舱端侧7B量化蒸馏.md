# 端侧 Qwen2.5-Omni-7B：量化 + 蒸馏怎么塞进车机芯片

> 元境智能座舱大模型落地实战系列第 13 篇。大模型动辄几十上百 G，车机芯片算力和内存都有限，怎么把模型塞进去跑起来？这篇讲量化 + 蒸馏。

---

## 一、问题：车机芯片跑不动大模型

座舱的多模态能力（疲劳检测、手势、情绪）要低延迟、数据不出车，所以模型要放端侧。但车机芯片（骁龙这类）算力、内存都远不如云端 GPU，一个几十 G 的大模型根本塞不下、也跑不动。

解决思路是两个字：**压缩**。具体靠**量化**和**蒸馏**。

## 二、量化：INT8 把模型压小 4 倍

量化是把模型参数从高精度压成低精度：

- 原始是 **FP32**（32 位浮点），一个参数占 4 字节；
- 压成 **INT8**（8 位整数），一个参数占 1 字节，**体积小 4 倍**。

为什么量化后还能加速？因为：

1. 整数运算比浮点快；
2. 占内存、带宽少；
3. 车机芯片的 **NPU 对整数运算有专门优化**。

量化是端侧部署大模型的标配手段。推理时把模型转成 ONNX 格式，用 **ONNX Runtime / TensorRT** 跑 INT8 量化推理。

### 量化会掉精度，怎么权衡

量化有代价——精度损失。我的做法是**在评测集上验证**：先量化，跑一遍准确率，损失在可接受范围（一般 1% 以内）就上；损失大了就用更细的量化方案（逐层量化、AWQ/GPTQ），或者用蒸馏补。

核心：**精度损失有评测兜底，别拍脑袋量化**。端侧对延迟要求高，只要精度损失可控，就优先换速度。

## 三、蒸馏：大模型教小模型

蒸馏是另一个压缩手段：**用一个大模型当"老师"，把它的能力"教"给一个小模型**。

老师模型输出软标签或中间特征，学生模型学着模仿。这样小模型能用更少参数，达到接近大模型的效果。

端侧 Qwen2.5-Omni-7B，就靠蒸馏把能力压出来——不是从零训一个 7B，而是让大模型"带"出一个小模型。

## 四、为什么是 Qwen2.5-Omni-7B

端侧模型选 Qwen2.5-Omni-7B，几个理由：

- **原生多模态**：文本、图像、音频一个模型统一处理，端侧不用拼多个小模型；
- **7B INT4 量化后约 4GB**，能塞进车机芯片内存，效果还够用；
- 更大（14B/32B）端侧扛不住——内存、算力不够；更小（1.5B/3B）能力不够，多模态理解会掉。

所以 Qwen2.5-Omni-7B 是"**塞得下 + 够用 + 多模态**"的平衡点。

## 五、端侧模型怎么更新（OTA）

端侧模型上线后要更新，走 **OTA 下发**，但要配好治理：

1. **灰度**：新模型先在灰度车机上验证，效果 OK 再全量；
2. **版本化**：每个模型版本带唯一标识，切换就是改配置指向新版本；
3. **回滚**：有问题秒切回旧版本。

端侧模型更新不能一把梭，否则翻车了没法退。

## 六、总结

可复用的三条：

1. 端侧跑大模型，靠**量化（INT8/INT4）+ 蒸馏**把模型压小。
2. **量化掉精度要评测集兜底**，损失可控才上。
3. 端侧尺寸选 **7B** 是"塞得下 + 够用"的平衡点，更新走**灰度 + 版本化 + 回滚**。

## 附：核心代码

```python
"""端侧 Qwen2.5-Omni-7B 量化部署（脱敏示意）"""
import onnxruntime as ort
from onnxruntime.quantization import quantize_dynamic, QuantType

# ① 动态量化：FP32 -> INT8，体积约小 4 倍
quantize_dynamic(
    "qwen_omni_7b.onnx", "qwen_omni_7b_int8.onnx",
    weight_type=QuantType.QInt8,
)

# ② 端侧推理：走车机芯片 NPU，低延迟
session = ort.InferenceSession(
    "qwen_omni_7b_int8.onnx",
    providers=["NPUExecutionProvider", "CPUExecutionProvider"],
)

def infer(input_ids, pixel_values=None):
    feeds = {"input_ids": input_ids}
    if pixel_values is not None:
        feeds["pixel_values"] = pixel_values
    return session.run(None, feeds)

# ③ 精度验证：量化前后跑评测集，损失 1% 内才上
def validate_quantization(test_set, fp32_model, int8_model):
    fp32_acc = eval_accuracy(fp32_model, test_set)
    int8_acc = eval_accuracy(int8_model, test_set)
    drop = fp32_acc - int8_acc
    assert drop <= 0.01, f"量化掉精度 {drop:.2%}，超预算"
    return int8_acc
```

关键：量化把 FP32 压到 INT8（体积小 4 倍），再用 NPU 跑；精度损失靠评测集兜底，损失 1% 内才上。
