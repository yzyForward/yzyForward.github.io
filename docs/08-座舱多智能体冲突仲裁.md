# 多智能体冲突仲裁：置信度 + 优先级 + DAG 确定性调度

> 元境智能座舱大模型落地实战系列第 8 篇。一句话触发多个领域 Agent、或者多个 Agent 结论冲突时，到底听谁的？这篇讲仲裁机制——而且是"可预测"的仲裁，不是"投票看运气"。

---

## 一、问题：冲突从哪来

多智能体协作里，冲突有两种典型情况：

1. **一句话触发多个领域**：用户说"回家路上帮我开空调"，横跨导航、车控、车家互联三个领域，谁先谁后、谁主导？
2. **多个 Agent 结论打架**：语音 Agent 判断是"开窗"，视觉 Agent 判断是"关窗"，听谁的？

如果没个仲裁规则，要么几个 Agent 抢着响应，要么随机选一个，结果不可复现。

## 二、方案：三层仲裁规则

我的仲裁分三层，按顺序走：

### 1. 置信度排序

每个 Agent 输出时带置信度。先按置信度排——**谁更确定听谁的**。这是第一层，直觉上最合理。

### 2. 领域优先级

置信度差不多时，按领域优先级定。座舱里安全永远最高：

**安全 > 导航 > 车控 > 娱乐 > 主动服务**

为什么安全最高？疲劳提醒、儿童遗忘、危险操作拦截，哪怕置信度略低，也要优先响应或升级人工——因为错过安全事件的代价远大于错过一条娱乐推荐。

### 3. DAG 依赖关系

有些冲突不是"二选一"，而是"有先后"。比如"先导航、再到家提醒"，这是依赖关系，不是竞争关系。

用 **DAG（有向无环图）** 表达任务依赖：哪些必须串行（先导航再提醒）、哪些能并行（导航和开空调可以同时）。DAG 把"谁先谁后"也定死了。

## 三、为什么不用"辩论投票"

多智能体仲裁，有一种流行做法是**辩论投票**——几个 Agent 各自发表意见，投票决定。我不用它当主机制，原因是：

1. **结果不确定**：投票结果随各 Agent 的表现波动，不可复现。
2. **怕"多数人一起错"**：几个 Agent 同时幻觉，投出同一个错误答案，投票反而放大了错误。

车规要**可预测、可复现、可审计**，所以用"置信度 + 优先级 + DAG"这套确定性规则——同样输入，每次结果一致，好测试、好过安全认证。

## 四、拿不准怎么办：多轮澄清 + 人工

确定性规则也有覆盖不了的时候——置信度低、优先级也分不出、或者本身就是模糊需求。这时候不硬赌：

1. **多轮澄清**：反问用户确认意图（"你是想开空调还是开车窗？"）；
2. **高危升级人工**：涉及安全、资金、异常处置的，结论不发出去，必须人工确认。

原则：**拿不准就问，别猜。** 座舱猜错一次，可能就是一次误操作。

## 五、为什么把"调度"和"仲裁"拆开

一个容易忽视的设计点：调度和仲裁要拆开。

- 调度负责"派活"：把任务分给谁；
- 仲裁负责"断案"：冲突了听谁的。

如果同一个模块既派活又断案，等于既当运动员又当裁判，出错时没人纠偏。拆开后各管一段、责任清晰。

## 六、总结

可复用的三条：

1. 仲裁按 **置信度 → 优先级 → DAG** 三层，确定性可复现。
2. 车规**不用辩论投票**，因为结果不确定、怕多数一起错。
3. 拿不准就**多轮澄清 + 高危人工**，不硬赌；调度和仲裁**拆开**，避免既当运动员又当裁判。

```python
PRIORITY = {"安全": 0, "导航": 1, "车控": 2, "娱乐": 3, "主动服务": 4}

def arbitrate(results):
    # 1. 置信度排序：谁更确定听谁的
    results.sort(key=lambda r: -r["confidence"])
    # 2. 领域优先级：安全永远最高
    results.sort(key=lambda r: PRIORITY.get(r["domain"], 99))
    top = results[0]
    # 3. 低置信澄清 / 高危人工兜底
    if top["confidence"] < 0.6:
        return clarify()            # 拿不准就问，不硬赌
    if top["domain"] == "安全":
        return human_confirm(top)   # 安全类必须人工确认
    return top
```

关键：这套仲裁是确定性的——同样输入每次结果一致，好测试、好过安全认证，不靠投票碰运气。
