## 一、项目背景：车企为什么需要大模型座舱

传统语音座舱只能听懂固定几句指令——"打开空调""导航到某地"。用户换个说法它就听不懂，更别提理解"我有点累""帮我找下那个东西"这类真实意图了。

大模型出现后，座舱有了质变的可能：

1. **自由对话**：从固定指令到自然语言理解，想怎么说就怎么说。
2. **跨域办事**：一句话"回家路上帮我开空调"能串联导航、车控、车家互联多个能力。
3. **看懂状态**：加了视觉后，疲劳、分心、儿童遗忘这些"用户不会自己说"的状态也能被感知，做主动服务。

我们的目标就是：**把座舱从"听懂指令"推进到"看懂状态、主动办事"**。

## 二、三个项目一条线（项目情况）

这个项目不是一口气做完的，而是三个项目递进，一条线串起来：

| 阶段 | 项目 | 时间 | 解决什么 |
|------|------|------|---------|
| 1 | **知识底座（RAG）** | 2024.06–2024.11 | 把座舱知识结构化，让答案"有据可查" |
| 2 | **中枢平台（多智能体）** | 2024.12–2025.10 | 用"1 中枢 + N 领域"让车"会办事" |
| 3 | **多模态升级** | 2025.09–2026.09 | 加视觉，让车"看懂状态" |

**逻辑关系**：先有知识（能查）→ 再有编排（能办事）→ 最后加感知（能看懂）。三个项目是从下到上、从内到外的演进。

- **知识底座**：给上层多智能体提供带出处的检索，是"知识层"。
- **中枢平台**：多智能体编排，是"编排层"，它把知识底座封装成知识检索 Agent 接入。
- **多模态升级**：在编排骨架上加视觉这条感知线，复用原有的调度、仲裁、主动服务机制。

## 三、技术选型（为什么是这一套）

选型总原则：**能私有化、和生态一致、按端云分工选尺寸**。

### 基座模型：千问生态一路用下来

| 位置 | 模型 | 干什么 | 为什么 |
|------|------|--------|--------|
| 端侧（车机芯片） | **Qwen2.5-Omni-7B**（INT8 量化 + 蒸馏） | 唤醒、轻量意图分类、视觉实时初筛、人脸脱敏 | 原生多模态（文本/图像/音频），7B 量化后塞得进车机，生物信息本地闭环 |
| 云端（GPU） | **Qwen3-VL** | 非敏感视觉：找物品、车外环境理解 | 视觉理解 + 推理一体 |
| 云端（GPU） | **文本 LLM**（Qwen2.5/Qwen3） | 疲劳/分心复核、多模态融合决策 | 端侧已输出结构化特征，云端不用再看原始图像 |

> 为什么一路用千问？从中行的 Qwen1.5 试点，到车企的 Qwen2、Qwen2.5、Qwen2.5-Omni、Qwen3-VL，生态一路用下来，tokenizer、部署栈、调优经验都能复用，上手快。

## 四、技术方案：整体架构

整体分五层：

```
┌────────────── 接入层 ──────────────┐
│  语音 / 摄像头 / 手势（多模态输入）  │
└───────────────────────────────────┘
          │
┌────────────── 感知层 ──────────────┐
│ 端侧 Qwen2.5-Omni-7B（唤醒/意图/   │
│  视觉初筛/人脸脱敏，150ms 内）      │
└───────────────────────────────────┘
          │ 结构化特征 + 脱敏非敏感帧
┌────────────── 编排层 ──────────────┐
│  MasterAgent（意图理解/任务分解/    │
│  路由）+ N 个领域 Agent            │
└───────────────────────────────────┘
          │
┌────────────── 知识层 ──────────────┐
│  RAG 知识底座 + 知识图谱 + 记忆      │
└───────────────────────────────────┘
          │
┌────────────── 治理层 ──────────────┐
│  版本/权限/缓存/评测/数据飞轮/人在回路│
└───────────────────────────────────┘
```

### 端云协同（核心设计）

按"**低延迟 + 隐私 → 端侧，复杂推理 → 云端**"切分：

- **端侧**：唤醒、轻量意图分类、视觉实时初筛、人脸脱敏——生物信息不出车。
- **云端**：非敏感视觉（找物品）、多轮推理、融合决策。

数据流：**端侧结构化特征 + 脱敏非敏感帧 → 云端**。原始人脸、语音不出车。

### 数据飞轮

```
Kafka 采集日志 → 接管率挖 Bad Case → 人工复核
  → 定向采样 + 数据增强 → LoRA 微调小模型 + Prompt 优化大模型
  → Langfuse 评测回归 → 灰度上线 → 再采集
```

让模型越用越准，疲劳误报率从 8% 降到 3% 就是靠这个闭环。

## 五、核心代码：端云协同的骨架

```python
# 端云协同的核心：任务按"低延迟+隐私 / 复杂推理"分流
EDGE_TASKS = {"唤醒", "意图分类", "疲劳初筛", "人脸脱敏"}
CLOUD_TASKS = {"找物品", "车外理解", "多轮推理", "融合决策"}

def dispatch(task, frame=None, audio=None):
    """端云分流：生物信息/低延迟任务端侧本地处理"""
    if task in EDGE_TASKS:
        # 端侧 Qwen2.5-Omni-7B：本地闭环，150ms 内
        result = edge_model(task, frame=frame, audio=audio)
        # 人脸脱敏：无生物特征后才可能外传
        if frame is not None and "face" in result:
            result["frame"] = blur_faces(frame)   # 高斯模糊/马赛克
        return result
    # 云端：只处理非敏感任务
    return cloud_invoke(task, frame=result.get("frame"), features=result)

def blur_faces(frame):
    """端侧人脸检测 + 高斯模糊，确认无生物特征后加密上传"""
    faces = face_detector(frame)
    for x, y, w, h in faces:
        frame[y:y+h, x:x+w] = gaussian_blur(frame[y:y+h, x:x+w])
    return frame
```

这段代码是整条端云链路的骨架：**端侧任务本地闭环、人脸先脱敏再外传、云端只碰非敏感数据**。
