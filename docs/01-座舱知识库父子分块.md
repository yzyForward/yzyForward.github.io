# RAG 父子分块：召回精度和上下文完整性，怎么兼得？

> 这是"元境智能座舱大模型落地实战"系列的第 1 篇。我会结合一个真实的车企座舱知识库项目（脱敏后），讲清楚 RAG 里最容易踩坑、也最影响效果的一步——文档分块。

---

## 一、背景：RAG 为什么要分块

RAG（检索增强生成）的基本思路很简单：把知识库里的文档切成一堆小块，向量化存进向量库；用户提问时，检索出最相关的几个块，和问题一起喂给大模型生成答案。

分块是整个链路的地基。为什么必须分？因为 Embedding 模型的输入长度有限，而且整篇文档向量化后语义会被"稀释"——一篇一万字的手册压成一个向量，里面混了几十个主题，检索时根本分不清哪段和问题相关。

所以要把文档切成小块，让每个块聚焦一个语义点，检索才能准。

## 二、分块的两难：切太小 vs 切太大

切块大小是 RAG 里最经典的矛盾：

- **切太小**（比如一句话一块）：语义不完整。关键信息可能正好被切在边界，检索时"只召回半句"，模型看到的是残缺上下文，答不对。
- **切太大**（比如一千字一块）：一个块里塞了多个主题，向量被稀释。检索时相关和不相关的内容混在一起，召回精度下降，还浪费 token。

我一开始就是固定 500 字切，结果发现两个问题都沾：语义聚焦不够、上下文又总被切断。调来调去，最后换成了**父子分块**。

## 三、父子分块的思路：职责分离

核心思路一句话：**把"召回"和"生成"要的东西分开，用两种粒度的块各干各的。**

- **子块（Child Chunk）**：小粒度，200～400 字，用来**做向量化和召回**。块小、语义聚焦，检索准。
- **父块（Parent Chunk）**：大粒度，把相邻章节聚合成一个较大的上下文块，**只做上下文、不生成向量**。块大、信息全，喂给模型时上下文完整。

关键点在于：**父块不生成向量、不参与召回**。

为什么要这么设计？如果父块也向量化，召回粒度就被拉粗了，小粒度子块的优势就没了；如果只用子块，模型只能看到孤零零的一小段，看不到前后文，答案质量差。职责分开，两全。

## 四、具体设计

我在座舱知识库上是这么落的：

### 1. 子块：200～400 字 + 相邻重叠

- 子块大小定在 200～400 字，是拿评测集试出来的——这个区间对功能说明、话术这类短文本，刚好是一个相对完整的语义单元。
- 相邻子块之间保留**重叠**，避免关键句正好被切在两块边界。比如"开启座椅加热"这句话，如果硬切，可能"开启座椅"在一个块、"加热"在下一个块，检索就漏了。

### 2. 父块：聚合相邻章节

父块把相邻章节聚合起来，作为完整上下文。比如子块是"座椅加热的操作步骤"这一小节，父块就是包含它的整章"座椅功能"，把前置条件、注意事项都带上了。

### 3. 锚点：四层元数据

每个块都打上「文档—章节—场景—意图」四层锚点。这一步很容易被忽略，但很重要：

- 后面做**过滤下推**（按功能域、场景过滤）要靠它；
- **引用回填**（答案标注出处、页码）要靠它；
- 出问题定位"这个块来自哪个文档哪一章"也要靠它。

### 4. 表格：整表保留，不切散

文档里的表格是重灾区。表格的语义高度依赖结构——表头一丢，数字就没含义了。所以：

- 表格**整表保留**，不按行硬切；
- 超长表格按行分组，但**每组复制表头**。

比如一张"功能名 → 参数 → 说明"的表，切的时候宁可大一点，也不能把表头和内容拆开。

## 五、检索时的两段式：召回用子块、生成用父块

这是父子分块的精髓，检索流程变成两段：

1. **召回阶段**：向量检索命中的是**子块**（小、准）。
2. **生成阶段**：把命中的子块替换成它所属的**父块**（大、全），喂给大模型。

一句话总结：**召回用小的，生成用大的。**

工程实现上，父块作为独立列复制进向量库，检索命中了子块，就能直接取到对应的父块文本，不用回数据库再查一次，少一次往返。

## 六、参数怎么定

- **子块 200～400 字**：太小语义不完整、太大稀释，实测这个区间召回率最好。
- **重叠**：相邻子块保留少量重叠，不用太多，10%～20% 即可，多了浪费存储和 token。
- **父块大小**：按章节聚合，别硬设固定值——手册的章节结构本身就是天然的父块边界。

这些都不是拍脑袋，是在评测集上对比出来的。**任何分块策略，最后都要落到"召回率说话"**。

## 七、踩过的坑

1. **表格切散**：表头一丢，数字全废。这是最早踩的坑，后来改成整表保留 + 复制表头。
2. **父块也参与向量化**：一开始图省事，父块也向量化，结果召回粒度被拉粗，精度上不去。父块必须只做上下文。
3. **子块切太碎**：一句话一块，语义不完整，召回噪声暴增。
4. **没打锚点**：后面要按场景过滤、做引用回填时发现没元数据，只能返工重抽。锚点从第一天就要设计进去。

## 八、效果

这套父子分块 + 后面几篇会讲的混合检索、精排、查询改写一起上，最终在评测集上：

- Top5 召回率：68% → 90%
- 引用准确率：95% 以上

分块是地基，它对了，后面的检索、精排才有意义。

## 九、总结

父子分块解决的是 RAG 里最根本的矛盾——**召回要"小"、生成要"全"**。解法不是折中，而是**职责分离**：子块管召回、父块管上下文，谁也别越界。

可复用的三条：

1. 子块小（200～400 字）做向量化，父块大只做上下文，**父块不参与召回**。
2. 检索命中的是子块，喂给模型的是父块，**两段式**。
3. 表格整表保留、锚点从第一天就设计，**别等返工**。

## 附：核心代码

```python
"""父子分块实现（脱敏示意）"""
from __future__ import annotations
import hashlib
from dataclasses import dataclass

@dataclass
class ChunkConfig:
    child_size: int = 300        # 子块 200~400 字
    overlap: int = 50            # 相邻重叠，避免边界切断
    min_child_len: int = 50      # 过短子块丢弃
    keep_table: bool = True      # 表格整表保留、不切散

@dataclass
class ParentBlock:
    id: str
    text: str                    # 只做上下文，不生成向量
    doc: str
    chapter: str
    scene: str
    intent: str

@dataclass
class ChildBlock:
    text: str                    # 做向量化
    parent_id: str
    chunk_hash: str = ""

class ParentChildChunker:
    """子块召回、父块补上下文，职责分离"""
    def __init__(self, cfg: ChunkConfig = ChunkConfig()):
        self.cfg = cfg

    def _make_parent(self, doc, ch: dict) -> ParentBlock:
        # 父块聚合章节，带上四层锚点，供过滤和引用回填用
        return ParentBlock(
            id=ch["id"],
            text=doc[ch["start"]:ch["end"]],
            doc=doc.title,
            chapter=ch["title"],
            scene=ch["scene"],
            intent=ch["intent"],
        )

    def _split_children(self, text: str, parent_id: str) -> list[ChildBlock]:
        step = self.cfg.child_size - self.cfg.overlap
        out: list[ChildBlock] = []
        for i in range(0, len(text), step):
            child_text = text[i:i + self.cfg.child_size]
            if len(child_text) < self.cfg.min_child_len:
                continue
            out.append(ChildBlock(
                text=child_text,
                parent_id=parent_id,
                chunk_hash=hashlib.md5(child_text.encode()).hexdigest(),
            ))
        return out

    def chunk(self, doc, chapters):
        parents, children = [], []
        for ch in chapters:
            # 表格：整表保留 + 复制表头，不切散
            if ch.get("is_table") and self.cfg.keep_table:
                children.append(ChildBlock(
                    text=ch["text_with_header"], parent_id=ch["id"]))
                continue
            parent = self._make_parent(doc, ch)
            parents.append(parent)
            children.extend(self._split_children(parent.text, parent.id))
        return parents, children


# 检索两段式：召回用子块、生成用父块
def retrieve_and_augment(query: str, topk: int = 5) -> str:
    hits = vector_search(query, topk=topk)        # 命中的是子块
    if not hits:
        return ""                                  # 缺证，上层走拒答
    parent_ids = {h["parent_id"] for h in hits}    # 父块去重
    parents = get_parents(parent_ids)              # 回取父块补上下文
    return "\n\n".join(p["text"] for p in parents)
```

核心：`parent` 只进库做上下文、不参与向量召回；检索命中 `child` 后，靠 `parent_id` 回取父块，一次就补全前后文。
