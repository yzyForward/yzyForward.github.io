# 1 中枢 + N 领域：车规多智能体为什么不用"大模型一把抓"

> 元境智能座舱大模型落地实战系列第 6 篇。RAG 做完了知识底座，接下来是怎么让大模型"办事"——从单点问答升级成多智能体。这篇讲整体架构的选择。

---

## 一、问题：为什么需要多智能体

做一个座舱助手，最省事的想法是"用一个大模型包打天下"——所有意图都交给它，它自己判断该干嘛。但真上线会暴露几个问题：

- **边界不清**：车控、导航、娱乐全混在一个模型里，错一处全盘乱。
- **幻觉不隔离**：车控出错了，可能污染导航的回答。
- **难并行**：一个模型串行处理，多领域任务快不起来。
- **难替换**：想单独升级某个领域，只能动整个模型。

所以换思路：**多智能体，分工协作**。

## 二、"1 中枢 + N 领域"的架构

我的做法是"1 中枢 + N 领域"：

- **1 个中枢（MasterAgent）**：统一做意图理解、任务分解、动态路由。它不干具体活，只负责"谁来做"。
- **N 个领域 Agent**：车控、导航、娱乐、健康、儿童陪伴……各管一块，专注自己领域的理解和执行，负责"具体怎么做"。

好处就是上面问题的反面：**边界清晰、幻觉局部化、可并行、可独立替换**。新增一个领域就是加一个节点，不用动中枢。

## 三、为什么车规不用"合同网竞标"

多智能体协作，有一种经典机制叫**合同网协议**（招标-投标-中标）：中枢发任务，各 Agent 投标报价，中枢评标选中标者。

但车规场景我**不用它当主机制**，原因是：

1. **多轮往返慢**：招标、投标、评标要好几轮通信，座舱要毫秒级响应，等不起。
2. **结果不确定**：谁中标取决于当时的投标情况，结果不可复现，而车规要"可预测、可审计"。

所以我的做法是**确定性路由为主**：高频意图直接按规则路由到对应领域 Agent，一次命中、确定可复现。只有模糊、多意图的场景，才走仲裁（下一篇讲）。合同网思想只在极端模糊场景做补充。

## 四、关键设计：图静态定义 + 动态路由

编排上还有一个细节：**图结构静态定义，路由用条件边动态选择。**

- 图结构写死：意图理解 → 路由 → 执行 → 反馈，这条大框架固定，保证**可复现、可审计**。
- 动态性放在"条件边根据状态选下一跳"，而不是运行时改图结构。

这样每次执行路径可预测，出了问题能回溯，也好过安全认证。

## 五、为什么这套适合车规

一句话总结车规的核心约束：**低延迟、可预测、安全。** 多智能体的不确定性（模型幻觉、竞标随机）天生和它冲突。所以架构上要做减法：

- 确定性路由为主，把不确定性关进笼子；
- 模糊才走模型推理 + 澄清；
- 高危操作人在回路。

## 六、总结

可复用的三条：

1. 多智能体的价值是**边界清晰、幻觉隔离、可并行、可替换**。
2. 车规用**确定性路由**，不用合同网竞标——因为要低延迟、可预测。
3. **图静态定义 + 条件边动态路由**，保证可复现、可审计。

```python
"""1 中枢 + N 领域（脱敏示意）"""
from typing import TypedDict
from langgraph.graph import StateGraph, END
from langgraph.checkpoint.memory import MemorySaver

class State(TypedDict):
    query: str
    intent: str
    confidence: float
    sub_tasks: list
    result: dict

# 确定性路由表：高频意图直接映射，不靠模型碰运气
ROUTE_TABLE = {"车控": "car_control", "导航": "navigation",
               "娱乐": "entertainment", "天气": "weather"}

def master_understand(state: State) -> State:
    """中枢：统一意图理解 + 任务分解，不干具体活"""
    intent, confidence = classify_intent(state["query"])     # 意图分类
    state.update(intent=intent, confidence=confidence)
    state["sub_tasks"] = decompose(state["query"], intent)  # 拆子任务
    return state

def route(state: State) -> str:
    # 高置信单意图走确定性路由，模糊/低置信走澄清
    if state["confidence"] >= 0.8:
        return ROUTE_TABLE.get(state["intent"], "clarify")
    return "clarify"

graph = StateGraph(State)
graph.add_node("understand", master_understand)     # 中枢：理解 + 分解
graph.add_node("car_control", car_control_agent)    # 各领域 Agent
graph.add_node("navigation", navigation_agent)
graph.add_node("entertainment", entertainment_agent)
graph.add_node("weather", weather_agent)
graph.add_node("clarify", clarify_agent)            # 低置信澄清
graph.set_entry_point("understand")
graph.add_conditional_edges("understand", route)    # 条件边动态路由
for n in ("car_control", "navigation", "entertainment", "weather", "clarify"):
    graph.add_edge(n, END)
app = graph.compile(checkpointer=MemorySaver())     # Checkpointer 持久化会话
```

关键：图结构写死（可复现、可审计），动态性只放在条件边；中枢只做理解和路由，不干具体活。
